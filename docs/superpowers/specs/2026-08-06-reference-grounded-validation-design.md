# 参考材料驱动的宽题型讲解生成设计

## 背景

当前 Demo 在生成讲解前，要求本地 Math Engine 独立求解题目、验证参考答案、验证每一步
等价变形，并验证近迁移题。这个策略在一元一次和一元二次数值方程上能够提供很强的
确定性保障，但它也把“能否生成讲解”绑定到了“本地求解器是否已经支持该题型”。

例如：

> 若 \(2n\)（\(n\ne0\)）是关于 \(x\) 的方程
> \(x^2-2mx+2n=0\) 的根，则 \(m-n\) 的值为多少？

参考解析通过代入 \(x=2n\) 得到
\(4n^2-4mn+2n=0\)，再利用 \(n\ne0\) 推出
\(m-n=\frac12\)。题目、答案和解析一致，但现有 Math Engine 只接受未知数 \(x\) 和
有限数值解集，因此把参数 \(m,n\) 判为非法符号，最终向用户报告“题目或参考答案未通过
数学验证”。

继续按题型扩展完整求解器并不可持续。这会把 Demo 的主要投入从教学设计、讲解质量、
互动和板书转移到自动解题与批改，而自动解题和批改不属于当前产品范围。

## 产品边界

本 Demo 的任务是：

> 根据题目、参考答案和可选参考解析，生成一节学生能听懂、能看懂、能够互动的数学讲解。

输入中的参考答案和参考解析是本次课堂的主要教学依据。系统可以独立审阅、交叉检查和
执行局部符号验证，但不要求在生成前独立解决所有题型。

本次不建设：

- 覆盖全部初中数学题型的自动求解器；
- 可用于正式批改、评分或判定学生答案对错的通用系统；
- 通用定理证明器、几何证明器或自然语言数学证明器；
- 对参考资料绝对正确的产品承诺；
- 每增加一种题型便增加一个专用求解模块的架构。

## 方案选择

### 方案 A：继续扩展严格符号求解

每出现一种新结构，就为 Math Engine 增加解析、求解、步骤验证和迁移题验证能力。该方案
在覆盖范围内最严格，但工程投入会持续追赶题库，无法服务“快速展示 AI 能把讲解做多好”
的核心目标。

### 方案 B：完全信任参考资料

直接跳过独立审阅，用题目、答案和解析生成课堂。该方案覆盖面最好，但无法发现答案与
解析互相矛盾、解析漏掉条件或讲稿偏离参考结论等明显问题。

### 方案 C：参考材料驱动、分层验证

采用该方案。

参考资料默认可以进入教学设计。现有符号工具继续验证它可靠支持的内容；独立模型负责
理解题目、抽取推导、交叉审阅和设计可执行的局部检查。严格符号路径出现可复现的明确
矛盾时才阻止生成。“当前工具不支持”或“无法完成形式化证明”不再等同于输入错误。

真实联调进一步确认：grounding 的检查请求本身也是模型产物，可能错误描述参考步骤。
因此这类请求的 `failed` 与 `unsupported` 都只能形成 warning；它们通过时可以提升
置信度，但不能承担自动批改或阻断权。

## 验证状态

生成链路使用三种互斥的验证模式：

```text
symbolic_verified
  现有 Math Engine 完整支持该任务，并验证了题目、答案和路线。

model_cross_checked
  任务不属于完整符号求解范围，但独立审阅与至少一项能够连接到最终结论的局部检查
  支持参考结论。

reference_grounded
  参考资料内部没有发现明确矛盾，但当前没有足够的可执行检查；课堂按参考资料生成。
```

验证结果另有一个一致性状态：

```text
consistent
  没有发现矛盾。

warning
  存在无法自动确认的步骤，但没有可复现的反例或冲突。

contradiction
  存在确定性工具已经复现的冲突。
```

在数学内容判断中，只有 `contradiction` 阻止生成。模型单独给出“可能不对”“置信度
不足”或与另一个模型意见不同，只能产生 `warning`，不能成为硬拒绝理由。字段长度、
危险字符、协议结构、隐私等输入安全问题仍按现有规则拒绝，不进入数学降级路径。

## 生成架构

### 1. 能力探测，而非题型准入

Math Engine 的入口从 `validate_problem()` 的全有或全无行为拆为能力探测：

```text
try_validate_problem(problem, reference_answer)
  -> supported + verified result
  -> supported + concrete contradiction
  -> invalid input
  -> unsupported
```

`unsupported` 表示工具边界，不表示输入错误。现有一元一次和一元二次数值方程继续走
`symbolic_verified` 路径，保留全部确定性验证。只有明确的能力边界错误，例如“出现参数
符号”“任务目标不是有限 \(x\) 解集”或“不是现有方程题协议”，可以返回 `unsupported`。
空输入、超长表达式、危险字符、非法运算符、超限指数和协议结构错误返回
`invalid input`，不能伪装成宽题型并交给模型。

### 2. Reference Grounding Agent

当题目不属于完整符号路径时，独立 Agent 将题目、参考答案和参考解析整理成
`ReferenceGroundingBrief`：

```text
ReferenceGroundingBrief
  task_summary: 本题要求什么
  target: 最终需要求出的量或结论
  assumptions: 题目中的条件，例如 n != 0
  reference_conclusion: 参考答案
  reasoning_steps: 参考解析中的连续推导
  method_name: 面向学生的方法名称，例如“代入法”
  check_requests: 建议执行的局部检查
  audit_notes: 缺失条件、跳步或表述风险
```

原始题目和参考资料仍被视为不可信引用文本，不能改变系统契约。Agent 只能输出结构化
内容，不能要求系统调用任意代码或工具。

如果没有参考解析，Agent 可以根据题目和参考答案补出一条候选讲解路线，但该路线只能
进入 `reference_grounded` 或 `model_cross_checked`，不能被标为完整符号验证。

### 3. 通用局部 Claim Checker

Claim Checker 不尝试独立解决整道题，只执行 Agent 提出的有限、结构化检查：

- 将给定值代入指定表达式或方程；
- 检查两个多项式表达式是否等价；
- 检查因式分解、展开和移项是否保持代数恒等；
- 在明确非零条件下检查约分；
- 把最终关系代回前面的等式，检查是否成立；
- 检查最终结论与参考答案文本是否一致。

它允许题目中出现有限数量的单字母实数符号，例如 \(x,m,n\)，并继续限制表达式长度、
运算数、指数、函数白名单和输入字符。它不接受任意 SymPy 代码，不执行模型生成的
Python，不尝试自然语言证明。

对于示例题，检查计划为：

1. 在 \(x^2-2mx+2n\) 中代入 \(x=2n\)，验证结果为
   \(4n^2-4mn+2n\)；
2. 验证 \(4n^2-4mn+2n=2n(2n-2m+1)\)；
3. 结合 \(n\ne0\)，验证从乘积为零可推出 \(2n-2m+1=0\)；
4. 验证该关系等价于 \(m-n=\frac12\)；
5. 用 \(m=n+\frac12\) 和 \(x=2n\) 代回原方程，结果化简为零。

这些是通用的代入、恒等、条件约分和回代检查，不需要增加“已知一个根求参数关系”
专用求解器。

### 4. 统一 Teaching Route

下游教学 Agent 不应区分“数值方程解集”与“含参关系”两套课堂协议。生成服务提供统一的
`TeachingRoute`：

```text
TeachingRoute
  verification_mode
  consistency_status
  method_name
  final_conclusion
  assumptions
  steps[]
    statement_before
    operation_explanation
    statement_after
    evidence_status
```

`symbolic_verified` 路径由现有 `MathRouteDraft` 转换而来；宽题型路径由
`ReferenceGroundingBrief` 和局部检查结果生成。`evidence_status` 可以是
`checked`、`cross_checked` 或 `reference_only`。

Lesson Director、Materials Agent 和 Reviewer 只读取该统一路线，不直接读取原始参考
解析，也不能修改最终结论、条件或步骤顺序。这样原有多 Agent 教学架构可以保留，同时
解除它对有限数值解集的依赖。

### 5. 互动与近迁移

宽题型模式继续使用选择题，不要求学生输入公式。

互动素材围绕当前 Teaching Route 中已经出现的认知转折设计，例如：

- 应该把 \(x\) 替换成哪个表达式；
- 为什么可以把等式两边除以 \(2n\)；
- 哪个条件保证约分合法；
- 哪个关系与当前等式等价。

选择题的正确项由 Teaching Route 的结论决定。结构、选项数量、选项唯一性、反馈完整性
和答案不泄露仍是确定性硬门；当 Claim Checker 支持时再验证选项数学含义。工具暂不支持
某个选项的语义时，由 Materials Agent 与 Reviewer 交叉审阅，不拒绝整节课。

近迁移在宽题型模式下也是参考路线驱动的选择题。它不再强制通过“求出有限 \(x\) 解集”
这一旧门禁，但必须满足：

- 题干与本课方法同构；
- 正确项唯一；
- Reviewer 能说明正确项依据；
- 错误项对应可解释的常见错误；
- 公开载荷继续隐藏正确项、逐项反馈和内部验证信息。

## 决策策略

完整决策顺序如下：

```text
输入题目、参考答案、可选参考解析
→ Math Engine 能力探测
→ 支持且验证通过：symbolic_verified
→ 支持且证明冲突：阻止生成，返回具体可修正原因
→ 不支持：Reference Grounding Agent
→ 生成结构化推导和检查请求
→ Claim Checker 执行可支持的局部检查
→ 局部检查失败或不支持：warning，继续按参考材料生成
→ 至少一项连接到最终结论的检查支持结论：model_cross_checked
→ 没有可执行检查但无矛盾：reference_grounded
→ 生成 Teaching Route
→ Lesson Director 设计讲解与板书
→ Materials Agent 生成选择互动与近迁移
→ Reviewer 审查整篇讲稿与参考路线的一致性
→ 编译、生成火山语音、进入全屏课堂
```

## 硬拒绝与软降级

### 可以硬拒绝

- 支持范围内的 Math Engine 证明参考答案与题目不一致；
- Claim Checker 复现了具体等式不成立、非法约分或回代失败；
- 参考答案与参考解析直接给出不同结论，且无法通过规范化消除差异；
- Teaching Route、讲稿或选项修改了已确定的最终结论；
- 生成内容违反结构、安全、隐私或答案泄露约束。

### 不应硬拒绝

- 题目包含 \(m,n,a,b\) 等参数；
- 任务不是求 \(x\) 的有限数值解集；
- 当前 Math Engine 不认识该题型；
- 解析中存在自然语言步骤，无法完全转换成符号表达式；
- 独立模型给出低置信度，但没有指出可复现的矛盾；
- 某个互动或近迁移选项无法被现有符号工具完整验证。

## 用户体验

生成页不再把 `unsupported` 显示为“题目或参考答案未通过数学验证”。用户仍看到统一的
生成阶段，不暴露内部 Agent 分歧或调试信息。

明确矛盾时返回可操作信息，例如：

> 参考解析最后得到 \(m-n=\frac12\)，但参考答案填写为 \(m-n=2\)。请检查后再试。

无法完整自动验证时继续生成，不在学生课堂中显示“未经验证”标签。验证模式保存在服务端
`validation_report`，供 Demo 研发与教师审阅使用，不发送到公开课堂载荷。

## 失败处理

- Reference Grounding Agent 输出结构无效：重试一次；仍失败时返回“暂时无法整理参考
  解析”，不伪装成数学错误；
- Claim Checker 无法解析某项检查：记录 `unsupported`，继续执行其他检查；
- 所有检查均不支持：进入 `reference_grounded`，继续生成；
- Agent 与参考资料意见不同但没有确定性证据：记录 warning，继续生成；
- Reviewer 发现讲稿偏离 Teaching Route：按现有机制最多修订两轮；
- TTS、编译和运行时失败继续沿用现有整课失败策略。

## 兼容性与迁移

- 现有数值方程测试、确定性路线和数学步骤验证保持不变；
- 已保存的 `RuntimeLesson` 不需要迁移；
- `validation_report` 增加验证模式和一致性状态，但继续只保存在服务端；
- 原有 `required_method` 仍适用于因式分解法、公式法和配方法；宽题型允许从参考路线得到
  开放的方法名称，例如“代入法”“整体代入”或“利用根的定义”；
- 新增宽题型路径时，不改变选择题判分、反馈隐私、KaTeX、板书运行时和火山 TTS 接口。

## 测试与验收

### 回归测试

- 现有一元一次、二次方程继续进入 `symbolic_verified`；
- 支持范围内的错误参考答案继续被硬拒绝；
- 现有确定性数学路线、选择互动和近迁移校验全部保持通过。

### 宽题型测试

- 示例含参根题进入 `model_cross_checked`，最终结论为
  \(m-n=\frac12\)；
- 同题没有参考解析时可以进入 `reference_grounded` 并生成课堂；
- 参数字母本身不会触发“题目错误”；
- 局部代入、因式分解、条件约分和回代检查分别有独立单元测试；
- Claim Checker 不支持的请求会软降级，不阻止生成；
- 可复现的错误回代会产生 `contradiction` 并阻止生成；
- 模型文字分歧但无工具证据时只产生 warning；
- 宽题型近迁移不再调用有限 \(x\) 解集验证。

### 安全与隐私

- 任意模型输出不能执行 Python、导入模块或访问属性；
- 表达式长度、字符、符号数、操作数和指数继续有上限；
- 公开课程载荷不包含参考答案、参考解析、验证报告、正确选项或未选择反馈；
- 提交选择后只返回本次所选选项的反馈和音频。

### 现场验收

使用真实 OpenAI 兼容 API 和火山 TTS 输入示例题、答案与多段解析，确认：

1. 生成任务不再因参数 \(m,n\) 被拒绝；
2. 讲解先说明“把已知根代回原方程”的依据；
3. 板书完整展示代入、提取 \(2n\)、使用 \(n\ne0\) 和得到最终关系；
4. 至少一个选择互动检查学生是否理解非零条件的作用；
5. 公式由 KaTeX 渲染，错误反馈可重试并播放语音；
6. 最终回到题目要求，明确得到 \(m-n=\frac12\)；
7. 课堂公开载荷不泄露答案和验证内部信息。

## 证据边界

`symbolic_verified` 表示当前受限 Math Engine 对支持范围内的数学对象完成了确定性检查；
`model_cross_checked` 表示参考路线经过独立模型审阅并通过至少一项能够连接到最终
结论的局部工具检查；
`reference_grounded` 表示课堂忠实依据参考资料生成，但没有完成形式化证明。

三种状态都不能证明参考资料绝对正确，也不能把本 Demo 表述为自动批改系统。教师评审和
学生学习效果仍是独立的产品验证工作。
