# 方法先行、公式渲染与诊断型选择题设计

## 背景

当前 Demo 已经能够根据题目、参考答案和解析文本生成完整讲解，并在全屏横屏课堂中
同步播放语音、板书动作和学生互动。本次改进解决三个会直接影响教学质量的问题：

1. 讲解可能直接进入代数操作，没有先让学生理解本课使用的方法；
2. 原题、板书和互动中的公式仍以普通文本显示；
3. 公式输入框要求学生使用键盘输入数学式，不适合横屏 Pad 的真实课堂体验。

这三个问题需要在教学生成协议、质量审核、课件编译和前端运行时中同时解决。仅修改
提示词无法稳定保证结果，仅替换前端文字样式也无法得到可靠的数学排版。

## 目标

- 每节课在执行解题步骤前先建立方法概念；指定使用配方法时，第一项教学重点必须是
  “配方法”，随后解释它的目标形式和作用；
- 原题、板书、比较层、互动题干、选项、提示与总结中的数学式能够正确排版；
- 新生成课件不要求学生键入公式，自动判分的数学互动使用选择或板书点选；
- 错误选项对应可解释的常见错误，选错后给出针对性反馈并允许重试；
- 最终近迁移题继续验证同一方法结构，同时改为选择题；
- 保留现有全屏横屏 Pad、语音播放、语义板书动作和临时图层返回主板的体验。

## 不在本次范围

- 不实现通用数学公式编辑器或手写识别；
- 不建立完整公式抽象语法树、字符级坐标和局部笔迹动画；
- 不把所有课堂互动机械地改成选择题：有明确板书对象时仍可使用点选；确有必要的
  一句话反思可以保留，但不自动判错；
- 不改变 OpenAI 兼容模型接口和火山引擎 TTS 服务；
- 不将视觉正确或自动测试结果表述为已经证明学生学会了。

## 方案选择

### 方案 A：只修改生成 Prompt

开发量最小，但模型仍可能跳过方法解释，公式仍是纯文本，近迁移也会继续出现输入框。
该方案不能解决运行时的稳定性问题。

### 方案 B：教学结构、渲染运行时和互动协议协同修改

这是采用的方案。结构化方法介绍保证讲解顺序，数学渲染器统一负责公式呈现，选择题
协议提供可执行的选项、正确答案和针对性反馈，Reviewer 与确定性校验共同兜底。

### 方案 C：完整数学教学 DSL 与公式 AST

该方案能够支持字符级变形和几何标记，长期能力上限更高，但会扩大当前 Demo 的范围，
并显著增加模型输出协议与渲染器复杂度。本次保留可演进接口，不直接实施。

## 教学体验

以“用配方法解一元二次方程”为例，课堂顺序如下：

1. 主板展示原题，语音给出本课任务；
2. 临时教学层首先写出并突出“配方法”，不圈住屏幕上唯一的整条公式；
3. 用学生语言解释：“配方法就是把二次式整理成完全平方的形式”；
4. 展示目标形式 \((x-a)^2=b\)，解释它为什么有用：开平方后可转成两个一次方程；
5. 返回原题主板，只突出当前决定配方数的局部，例如一次项系数 \(-6\)；
6. 设置选择题：“为了配成完全平方，等式两边应该同时加多少？”；
7. 对每个错误选项播放与错误原因对应的短反馈，学生可重新选择；
8. 继续完成配方、开平方、分支求解和结果检查；
9. 用同结构、不同表面的选择题完成近迁移。

方法介绍是解题主线的入口，不是固定播放的百科定义。Director 可以决定语言、类比和
节奏，但必须在第一次实质性代数变形之前说明方法名称、学生可懂的定义、目标形式以及
该方法怎样降低问题难度。

## 数据模型

### 方法介绍

`LessonDraft` 新增必填的 `method_introduction`：

```text
MethodIntroduction
  method_name: 方法名称
  student_definition: 学生能够听懂的一句话定义
  target_form: 本方法希望得到的数学形式
  why_it_helps: 该形式怎样让后续求解更容易
```

当输入带有 `required_method` 时，方法名称必须与指定方法一致。没有指定方法时，
Director 可以根据独立验算结果选择方法，但仍须生成完整的方法介绍。

Compiler 在原题开场之后、普通 `moments` 之前生成方法介绍教学段。该段使用
`micro_explanation` 图层，并在进入下一段时返回原题主板。板书动作固定使用语义对象
`method_name` 和 `method_target_form`；方法名称可以使用 `focus` 或下划线，不对唯一
公式执行整式 `circle` 或 `box`。

### 数学文本

模型生成的板书、互动题干、选项、反馈和总结中的数学片段统一使用 `\( ... \)` 行内
分隔符或 `\[ ... \]` 展示分隔符，内部使用 LaTeX 语法。普通中文仍为纯文本。
`narration` 是直接交给 TTS 的口语讲稿，必须使用自然中文表达数学含义，不放入
LaTeX 命令；精确公式同步写入同一教学段的板书动作。

原始题目不要求用户手工书写 LaTeX。运行时数学文本模块负责：

- 识别明确的 LaTeX 分隔符并交给公式渲染器；
- 将当前无图方程题中常见的 `x^2`、等号、括号和四则运算片段规范化后渲染；
- 保留原始中文文本和可访问名称；
- 公式解析失败时显示原始文本，不中断语音、板书或互动。

`BoardAction.content`、互动题干、选项、提示、正确反馈和课堂总结共用同一个安全渲染
入口，避免各区域出现不同的公式规则。

### 诊断型选择题

新生成课件的自动判分互动只允许 `choice` 或 `point_select`。运行时暂时保留
`expression` 和旧 `transfer` 的兼容读取能力，但 Director 不再生成这两类输入框。

`InteractionOption` 扩展为：

```text
InteractionOption
  option_id: 稳定且不泄露正确性的标识
  label: 学生看到的文本或公式
  feedback: 选择该项后播放和显示的短反馈；旧课件中可以为空
```

选择题必须有 3 至 4 个互异选项。错误选项不能是随机数字，必须对应本题真实可能出现
的错误，例如“忘记取一半”“取一半但没有平方”“直接把一次项系数平方”或“只改变
等式一边”。正确选项的反馈说明其成立原因，错误反馈先指出当前思路的具体偏差，再给
一个可以重新观察的线索，不直接公布正确选项。

前端提交 `option_id`，后端继续用稳定标识判分。前端根据本次所选 option 显示对应
feedback；音频服务为每个选项反馈预生成语音。答错后恢复全部选项供学生重试，答对后
播放正确反馈并进入后续讲解。

Schema 对 `feedback` 提供空值兼容，保证旧课件仍能读取；Generation 的确定性质量门
要求所有新生成选项都提供非空反馈。

### 近迁移

`TransferItem` 增加 `options` 和 `correct_option_id`，同时保留数学意义上的
`expected_answer` 供 MathEngine 独立验证。近迁移选项使用单独的 `TransferOption`：

```text
TransferOption
  option_id: 稳定标识
  label: 学生看到的公式
  canonical_answer: 数学引擎验证使用的纯文本答案
  feedback: 选择后的针对性反馈
```

这样公式展示可以使用 LaTeX，而数学引擎继续验证 `x=...` 形式的规范答案，不需要从
排版字符串反向猜测数学含义。Compiler 将近迁移编译成普通 `choice` interaction，
并把 `TransferOption` 映射为可显示的 `InteractionOption`，不再编译为 `transfer`
输入框。

确定性质量门验证：

- `correct_option_id` 指向存在的选项；
- 正确选项的 `canonical_answer` 与 `expected_answer` 等价；
- 其他选项的 `canonical_answer` 可以被数学引擎解析，且不与
  `expected_answer` 等价；
- 选项标识唯一，标签互异；
- 近迁移题本身与参考答案通过现有题目验证。

为兼容旧课件，`TransferItem.options` 默认空列表，`correct_option_id` 默认空值；
Compiler 只对旧数据保留原来的 `transfer` 输入交互。Generation 质量门要求所有新
草稿必须提供完整的近迁移选择题。公开课程接口继续移除 `expected_answer`，并同时
移除 `canonical_answer`，浏览器只接收显示标签、反馈和 option id。

## 公式渲染

前端使用本地静态 KaTeX 资源，不依赖课堂播放时访问 CDN。新增一个独立数学文本模块，
负责分段、规范化和安全渲染；`lesson.js` 只调用该模块，不直接拼接模型输出的 HTML。

安全和失败策略：

- KaTeX 使用 `trust: false`，不允许模型内容产生受信任链接、样式或命令；
- 只有数学片段进入公式渲染器，普通文本以 DOM text node 插入；
- 渲染失败时回退为原始数学字符串；
- 页面保留可访问文本，公式不会只以无语义图片呈现；
- 对已保存的旧课件继续支持 `x^2` 等普通写法。

公式渲染覆盖：

- 开场原题和学习目标；
- 主板、临时图层与比较板书；
- 课堂字幕中的旧式普通数学写法；新生成口语讲稿优先用自然语言；
- 互动题干、所有选项、提示与正确反馈；
- 方法总结和近迁移题。

## 生成与审核质量门

Lesson Director 新增以下约束：

- `method_introduction` 必须完整；
- 第一次实质性运算前必须完成方法介绍；
- 指定配方法时，第一项重点是“配方法”和目标形式，而不是直接突出整道题；
- 板书、互动和总结中的数学内容使用统一的 LaTeX 分隔符，口语 narration 不含
  LaTeX 命令；
- 自动判分互动使用 `choice` 或 `point_select`；
- 每个选择题有 3 至 4 个诊断性选项及逐项反馈；
- 近迁移提供可验证的选择题选项。

独立 Reviewer 将以下情况列为 `must_fix`：

- 未解释方法便开始变形；
- 只报出方法名称，没有说明目标形式或为什么有用；
- 公式语法无法渲染或同一公式写法不一致；
- 要求学生键入数学式；
- 错误选项为随机凑数、重复、等价或没有针对性反馈；
- 互动在作答前泄露正确选项；
- 临时方法图层没有回到原题主线。

确定性校验在 Reviewer 之前执行结构、方法匹配、选项唯一性、答案等价性和数学可解析
性检查。失败时沿用当前的一次整篇重新生成机制，不放宽质量门。

## 错误处理与兼容性

- 旧课程中的 `expression` 和 `transfer` 仍可播放和提交，避免改变历史运行时数据；
- 新模型草稿生成旧输入型互动时，确定性校验拒绝草稿并触发一次重新生成；
- 公式资源加载失败或单个公式解析失败时显示原文，课堂可以继续；
- 选项反馈音频生成失败沿用现有整课音频失败策略，不交付部分有声课件；
- 参考答案、解析文本和独立数学验证的既有冲突处理不变。

## 测试与验收

### Python

- Schema 测试覆盖方法介绍、逐项反馈和近迁移选择题约束；
- Generation 测试覆盖方法先行、禁止新输入型互动、诊断选项和数学等价校验；
- Compiler 测试证明方法介绍位于第一次解题 moment 之前，临时图层随后返回主板；
- API 测试证明选择题继续按 option id 判分，旧互动仍兼容；
- Audio 测试证明每个选项反馈获得稳定且安全的音频资源名。

### JavaScript

- 数学文本模块测试覆盖纯中文、带分隔符公式、旧式 `x^2`、混合文本和失败回退；
- 互动测试证明公式选项经过数学渲染，不再生成公式输入框；
- 选择错误选项时显示对应反馈并允许重试；
- 运行时状态机现有板书、图层、暂停和整式圈注防线继续通过。

### 浏览器现场验收

使用真实 OpenAI 兼容 API 和火山引擎 TTS 生成一节指定配方法的课程，横屏 Pad 全屏
检查以下路径：

1. 原题出现后先讲“配方法”；
2. 方法定义、目标形式和作用可听见、可看见；
3. 公式在原题、板书和选项中正确排版；
4. 第一次互动要求选择配方数，不出现公式键盘输入；
5. 至少两个错误选项产生不同的针对性反馈；
6. 选择正确后继续讲解；
7. 临时图层返回原题主板；
8. 最终近迁移使用选择题并可完成整课。

自动测试和浏览器验收能够证明结构、数学一致性与交互行为符合本设计。学生是否真正
理解配方法仍需要后续的小规模学生观察或教师评审，不能从 Demo 自身推断。
