# 参考答案与多段参考解析输入设计

日期：2026-08-06

状态：待用户复核

## 目标

真实题目数据包含三个不同层次的内容：

1. 题目文本；
2. 简短、明确的参考答案；
3. 可能包含多段文字、公式和步骤的参考解析。

本次修改保留参考答案的独立数学裁决作用，新增参考解析输入，并在教学设计前审阅
解析素材。系统不能把整段解析当成最终答案交给符号引擎，也不能未经检查就让
Lesson Director 照搬解析。

## 方案比较

### 方案 A：直接把参考解析交给 Lesson Director

实现成本最低，也能保留最多原始信息。缺点是解析中的错误步骤、答案冲突和提示
注入可能直接影响讲稿，无法满足 Demo 的质量要求。

### 方案 B：独立校验答案，先审阅解析，再设计课堂

这是本次采用的方案。Math Engine 独立验证题目与简短参考答案；Reference
Material Auditor 将参考解析视为不可信教学素材，提取方法、关键步骤、解释与
问题；可符号化的关键变形再由 Math Engine 验证。Lesson Director 同时获得独立
解集、审阅后的结构化素材和原始解析，但必须服从数学裁决与教学质量约束。

### 方案 C：完全使用规则解析参考解析

规则提取可控且成本低，但难以稳定处理不同题库来源的自然语言、换行、OCR 噪声
和公式排版。它可以作为明确答案与方程的辅助校验，不能单独承担解析理解。

## 输入契约

生成页包含以下字段：

- `problem_text`：题目文本，必填；
- `reference_answer`：简短最终答案，必填，例如 `x=1 或 x=5`；
- `reference_solution_text`：多段参考解析，可选，最多 12000 个字符；
- `required_method`：指定方法，可选；
- `lesson_length`：精讲或标准。

`reference_solution_text` 使用多行文本框，允许自然语言、空行和多行公式。页面
文案明确区分“参考答案”和“参考解析”。为了兼容只有题目与答案的数据和测试
场景，参考解析为空时沿用现有生成链路。

服务端只去除参考解析首尾空白，不压缩段落和行内空格。原始解析只在当前进程内
随课程对象保存，不进入学生课堂公开载荷，不写入日志，也不发送给 TTS。

## 系统角色

### Math Engine

Math Engine 继续拥有数学裁决权：

- 从题目中求出独立解集；
- 验证简短参考答案与独立解集一致；
- 验证 Auditor 提取出的、属于当前受支持代数范围的关键变形；
- 验证 Director 最终生成的完整数学路线。

### Reference Material Auditor

仅在填写参考解析时调用。它与 Lesson Director 使用隔离任务和结构化输出，把
参考解析当作引用数据而不是系统指令。它负责：

- 识别解析采用或建议的方法；
- 提取解析明确声称的最终答案；
- 提取解题主线、关键变形和可复用解释；
- 标出自相矛盾、答案冲突、跳步、表述含混或超出当前数学引擎范围的内容；
- 给出 `approved` 或 `rejected`，并附可定位到原文的证据。

Auditor 没有数学裁决权。它输出的最终答案必须由 Math Engine 与独立解集比较；
能够转换为受支持 `MathStep` 的关键步骤必须逐步验证。Auditor 不能因为解析写得
完整就覆盖独立数学结果。

### Lesson Director 与 Reviewer

Director 获得：

- 原题、简短参考答案和指定方法；
- Math Engine 的独立解集；
- 原始参考解析；
- Auditor 的结构化审阅结果。

原始解析在 Prompt 中明确标记为不可信引用材料，任何类似指令的文字都不得改变
系统契约。Director 可以借鉴正确的切入方式、理由和学生易懂表述，也可以补足
缺失步骤，但不能照搬已标记问题或绕过数学路线校验。

Reviewer 同时检查讲稿是否正确使用了经过审阅的参考素材，是否把解析中的错误、
无依据结论或不适合学生的表述带入课堂。

## 生成流程

```text
题目 + 简短参考答案
→ Math Engine 独立求解并核对答案

可选多段参考解析
→ Reference Material Auditor 结构化审阅
→ Math Engine 核对解析结论与可验证关键步骤

独立数学结果 + 审阅后素材
→ Lesson Director 设计完整课堂
→ 数学路线校验
→ Reviewer 整篇教学审核
→ TTS
→ 全屏课堂
```

没有参考解析时，不调用 Auditor，直接从已验证的题目与参考答案进入 Director。

## 阻断与降级规则

- 简短参考答案与题目真实解集冲突：阻止生成；
- 参考解析明确声称的最终结论与独立解集冲突：阻止生成；
- 参考解析中可识别的关键代数步骤改变了解集或运算不成立：阻止生成；
- 参考解析内部自相矛盾，无法确定可用主线：阻止生成；
- 参考解析只是不完整、跳过解释或缺少最终结论，但没有发现数学冲突：允许生成，
  由 Director 补足，Auditor 将缺口交给 Reviewer 重点检查；
- 解析包含超出首版符号引擎能力的旁注：不把该旁注当作数学事实，若不影响当前
  题目主线可继续生成，并在内部审阅结果中记录；
- Auditor 或供应商调用失败：按模型调用错误处理，不绕过审阅继续生成。

页面对可安全归因的输入问题给出明确提示：

- `参考答案与题目不一致，请检查后再试。`
- `参考解析与题目或参考答案存在数学冲突，请检查后再试。`

供应商响应、Prompt 和解析审阅细节不直接返回浏览器。

## 数据与公开边界

运行时课程对象可以保存原始参考解析，供服务端审计与后续复现。面向课堂的
`GET /api/lessons/{lesson_id}` 必须移除：

- `reference_answer`；
- `reference_solution_text`；
- Reference Material Auditor 的完整审阅记录；
- 内部数学与教学验证报告。

课堂只获得题目、已审核讲稿、板书动作、互动和音频 URL。

## 验证

测试按以下层次证明实现边界：

- Schema：接受保留段落的多行解析，拒绝空白伪值和超过长度的输入；
- 页面：参考答案保持独立单行输入，新增多行参考解析文本框和说明；
- API：三字段能够提交，公开课堂载荷不泄露参考答案或参考解析；
- Auditor：结构化审阅 Prompt 明确把解析视为不可信数据，输出满足严格 Schema；
- 数学质量：错误简短答案、冲突最终结论和无效关键变形都阻止生成；
- 兼容性：不填写参考解析时，现有生成链路与回归题继续工作；
- 生成质量：填写正确多段解析时，Director 与 Reviewer 均获得审阅后素材；
- 浏览器：使用真实多段解析完成一次生成，进入横屏课堂并播放语音。

这些检查只能证明输入处理、已识别冲突、结构化生成和浏览器执行符合契约。Auditor
仍是模型判断，无法证明它发现所有自然语言解析错误；最终课堂中的结构化代数路线
仍须由 Math Engine 独立验证，真实教学有效性仍需教师与学生评价。
