# 无图初中数学 AI 讲题 Demo 设计规格

版本：v0.1

日期：2026-08-05

状态：待用户复核

## 1. 目标

构建一个可以现场演示的 AI 讲题 Demo：

```text
输入题目文本、参考答案和可选指定方法
→ 通过 OpenAI 兼容 API 现场生成讲解
→ 校验数学内容
→ 审核并整体改写讲稿
→ 在横屏 Pad 尺寸的全屏课堂中逐步讲解
→ 通过重点板书、临时讲解图层和学生互动帮助理解
```

Demo 的核心价值是展示：对于一道首次输入的题目，AI 能把正确答案转化成一段连贯、有重点、有互动、面向学生理解的教学过程。

首版衡量的是单题讲解质量和技术可行性，不衡量题库规模、长期学习效果或平台完整性。

## 2. 首版范围

### 2.1 支持题型

- 一元一次方程；
- 一元二次方程；
- 一元二次方程支持因式分解法、公式法和配方法；
- 输入可以指定方法，未指定时由 AI 选择主方法。

### 2.2 输入

- 题目文本；
- 参考答案；
- 指定方法，可选；
- 讲解长度：精简或标准。

### 2.3 输出

- 一段经过整体审稿的学生讲解；
- 渐进板书及重点标注；
- 由讲解驱动的教学节拍；
- 一到三个有教学目的的互动；
- 必要时出现的临时讲解图层；
- 结果检查；
- 方法总结；
- 一道经过校验的近迁移题；
- 仅供开发排查的数学与生成校验报告。

### 2.4 首版不做

- 账号、班级、题库和学习历史；
- 长期学生画像；
- 通用知识图谱或复杂 RAG；
- 几何图形、函数图像、证明题和多问组合题；
- 数字人生成；
- MP4 合成；
- 学生任意追问后完全开放式改课；
- 多个 Agent 自由讨论或投票生成讲稿。

语音不是讲解质量的事实来源。首版可以把浏览器语音合成作为可选播放增强，核心验收仍以讲稿、板书、互动和数学正确性为准。

## 3. 产品体验

### 3.1 两个分离场景

Demo 包含两个视觉和功能上完全分离的页面。

**生成页**

只负责录入题目、参考答案、指定方法和讲解长度，并显示生成阶段。API Key、Base URL 和模型名通过服务端环境变量配置，不进入浏览器。

**全屏课堂**

生成完成后进入横屏 Pad 比例的全屏课堂。输入表单、调试字段和校验日志全部退出学生视野。课堂中的视觉中心是板书和当前认知任务，不采用左右分栏展示“输入”和“结果”。

### 3.2 课堂推进方式

课堂不一次性展示完整解析，而是沿着一条连贯教学主线逐步推进：

```text
建立目标与问题表征
→ 识别值得关注的结构
→ 选择或理解方法
→ 完成若干关键子目标
→ 在认知转折点让学生尝试
→ 检查结果
→ 压缩方法并完成近迁移
```

以上是教学功能，不是固定章节模板。AI 可以根据题目自由决定开场、节奏、类比、展开程度和互动位置。

### 3.3 学生控制

- 继续；
- 暂停；
- 返回上一个教学节拍；
- 重播当前教学节拍；
- 在互动中提交答案；
- 请求一级提示；
- 在结束时尝试近迁移题。

首版不允许任意跳到尚未讲解的完整答案，以避免破坏预测和互动。

## 4. 系统角色与判断权

首版采用“两 Agent、一数学引擎、一课堂 Runtime”。

### 4.1 Lesson Director Agent

Lesson Director 是整节课的唯一主创，负责从完整教学效果出发生成并修订讲解。

**知识输入**

- 题目、参考答案和指定方法；
- 经过数学引擎验证的状态与解集；
- 初中数学知识和常见误区；
- 初学者教学原则；
- 板书模态与动作能力；
- 可使用的互动类型；
- Reviewer 的整篇审稿意见。

**能力**

- 请求数学引擎解析、执行和验证；
- 生成完整讲解草稿；
- 设计重点、互动和临时讲解图层；
- 根据整篇审稿意见重写讲解；
- 发出明确的 `lesson_ready` 完成信号。

**判断权**

- 从哪里切入；
- 题目真正的教学难点；
- 方法选择理由；
- 哪些步骤压缩或展开；
- 何时互动；
- 何时打开临时图层；
- 怎样保持整节课叙事连贯。

Director 不能自行宣布未经数学引擎验证的公式、答案或互动正确答案。

### 4.2 Reviewer Agent

Reviewer 与 Director 使用隔离上下文，以学生理解和教研质量的视角审核整节课。

**输入**

- 原题和目标学生；
- 完整讲稿；
- 板书分镜；
- 所有互动及反馈；
- 所有临时图层；
- 数学校验报告。

**判断权**

- 判断讲解是否通过；
- 指出影响理解的整体问题；
- 指出需要修改的局部证据；
- 发出 `approved` 或 `revision_required`。

Reviewer 不分段代写，也不直接修改讲稿。Director 保留最终创作权，并根据审稿意见整体改写。

### 4.3 Math Engine

Math Engine 是确定性工具，不是 Agent。首版使用 SymPy。

它负责：

- 解析方程和表达式；
- 执行或验证代数操作；
- 比较表达式与解集；
- 检查指定方法；
- 检查参考答案；
- 校验学生输入；
- 校验近迁移题。

数学引擎拥有数学裁决权，但没有教学编排权。

### 4.4 Lesson Runtime

Runtime 负责执行已经通过审核的课程，并保存课堂状态：

- 当前教学节拍；
- 主板书状态；
- 临时图层栈；
- 当前互动；
- 学生作答历史；
- 当前提示等级。

Runtime 可以执行继续、暂停、判断回答、给提示、要求重试、进入临时图层和返回主板书。首版不允许 Runtime 自由重写核心讲稿。

自由文本理由可以现场调用 OpenAI 兼容 API 作有限分类；数值和代数式优先由数学引擎判断。以后需要开放追问和动态改课时，再把 Runtime 上方升级为 Tutor Agent。

## 5. 生成与质量机制

### 5.1 生成流程

```text
规范化输入
→ Lesson Director 理解题目并请求数学验证
→ Director 自由生成完整讲解草稿
→ Math Engine 校验讲稿中的数学对象和互动答案
→ Reviewer 审核完整讲稿和课堂分镜
→ Director 根据意见整体改写
→ 再次进行数学和一致性校验
→ 编译为课堂可执行内容
```

Reviewer 首次通过时不强制改写。Reviewer 要求修改时，Director 最多进行两轮结构化修订。仍未通过或数学失败时，系统返回明确失败原因，不生成看似完整的课堂。

### 5.2 硬约束

- 所有数学结论必须通过验证；
- 指定方法必须真正使用；
- 讲解不得与已验证解法冲突；
- 互动前不得提前泄露关键答案；
- 学生答案判断必须有可检查依据；
- 近迁移题和答案必须可验证；
- 临时图层退出后必须恢复原板书状态。

### 5.3 整篇质量审核

以下维度用于整篇判断和编辑建议，不作为要求每段逐项填写的模板：

- 学生能否沿着一条连贯主线跟上；
- 是否自然凸显决定方法的结构；
- 关键步骤是否说明“为什么”；
- 常规计算是否适当压缩；
- 互动是否发生在真实认知转折点；
- 错误反馈是否保留再次尝试机会；
- 临时图层是否帮助理解且能顺利返回主线；
- 讲解是否像老师面对学生说话；
- 结尾是否形成可以迁移的方法认识。

## 6. 板书系统

### 6.1 板书教学模态

AI 可以从以下模态中自由选择，单题不需要全部使用：

1. **渐进推演**：逐步写出推导，保留并弱化历史；
2. **结构聚焦**：从原题抽出决定方法的局部结构；
3. **变换演示**：呈现操作前后变化及保持不变的关系；
4. **对照比较**：比较正确与错误、方法或结构；
5. **互动留白**：遮住关键位置，等待学生作答；
6. **总结压缩**：把过程重组为可迁移的方法地图。

### 6.2 板书动作

首版支持：

- `write`：写入新内容；
- `transform`：从旧表达式过渡到新表达式；
- `focus`：突出目标并弱化其他内容；
- `annotate`：圈、框、括号、下划线、箭头和短标签；
- `compare`：并列展示可比较对象；
- `mask`：遮住尚未揭示的内容；
- `reveal`：揭示学生已尝试的内容；
- `fade`：降低历史步骤视觉权重；
- `pause`：保持当前画面并等待；
- `clear`：结束当前局部内容或切换板面。

圈注、高亮、遮罩和标记均属于首版基础能力。AI 引用语义对象并说明教学意图，不直接决定像素坐标、字体大小和动画曲线。

### 6.3 划重点原则

- 同一时刻只保留一个主要焦点；
- 黄色用于当前焦点；
- 绿色用于理由、条件和不变量；
- 红色仅用于真实错误和风险；
- 弱化其他内容通常优先于给更多内容变色；
- 圈注、箭头和标签在完成教学功能后可以淡出；
- 重点出现后需要留出阅读或思考时间。

### 6.4 临时讲解图层

课堂使用“基础板书 + 临时教学图层”的状态栈：

```text
保留基础板书
→ push_layer
→ 局部放大、拆解、对比或互动
→ 得到简短结论
→ pop_layer
→ 恢复原板书并继续
```

临时图层可以用于：

- 知识补充；
- 公式来源；
- 常见错误；
- 更简单的类比例子；
- 局部互动；
- 结构放大。

退出时可以把一条简短结论回写到基础板书，但不得改变已经验证的数学状态。

## 7. 学生互动

每节讲解由 Director 自由选择一到三个有意义的互动，不按数量机械填充。

### 7.1 支持形式

1. **点选结构**：学生在题目或板书中指出关键对象；
2. **选择判断**：选择方法、下一步或理由；
3. **填空与表达式输入**：填写数字、项或完整表达式；
4. **近迁移解答**：讲解结束后处理同结构的新题。

### 7.2 反馈策略

- 正确：确认结果，并补足最关键的理由后继续；
- 部分正确：指出已经正确的部分，只提示缺失点；
- 错误或不会：提供一级提示并要求重试；
- 再次错误：可以进入临时图层，用更小的等价问题或局部示范帮助理解；
- 完成临时讲解后：返回原问题或等价小问题再次作答。

首版不把“点击显示答案”视为完成互动。

## 8. 技术设计

### 8.1 技术栈

- Python 3.11 或更高版本；
- FastAPI；
- Pydantic；
- SymPy；
- OpenAI 兼容 Chat Completions API；
- 原生 HTML、CSS 和 JavaScript；
- 不使用数据库。

### 8.2 服务端配置

```text
OPENAI_BASE_URL
OPENAI_API_KEY
OPENAI_MODEL
```

服务端启动时检查配置，但不在日志和网页中输出 API Key。

### 8.3 服务接口

- `GET /api/health`：检查服务、模型配置和数学引擎；
- `POST /api/lessons/generate`：现场生成完整课程；
- `POST /api/interactions/evaluate`：判断自由文本理由或无法本地判断的回答；
- `GET /api/lessons/{lesson_id}`：读取当前进程内的课程；
- `GET /lesson/{lesson_id}`：进入全屏课堂。

课程只保存在当前服务进程的内存中。服务重启后可以丢失，符合首版 Demo 范围。

### 8.4 共享状态与 UI 更新

生成流程通过事件流向生成页报告：

- 正在理解题目；
- 正在验证数学路线；
- 正在设计完整讲解；
- 正在进行整篇审稿；
- 正在修订并编译课堂；
- 已完成或失败。

课堂 Runtime 和 UI 读取同一份课程状态。推进节拍、进入图层、提交回答和返回主板书都立即反映到画面，不维护相互独立的重复状态。

## 9. 失败与恢复

- 输入不在题型范围：明确返回“不支持的题型”；
- 参考答案与独立求解冲突：停止生成并指出冲突；
- 模型输出无法解析：要求模型按错误信息修复；
- 数学步骤失败：把具体失败步骤交回 Director 修订；
- Reviewer 不通过：最多进行两轮整体改写；
- 互动答案无法确定：不自动判错，提示学生换一种形式或标记为待确认；
- 临时图层异常：恢复进入图层前保存的基础板书状态；
- OpenAI 兼容 API 超时：显示失败阶段，允许用户重新生成。

失败不能降级为未经验证的完整讲解。

## 10. 验证方案

### 10.1 自动测试

- 题目与参考答案解析；
- 一元一次方程求解和等价检查；
- 一元二次方程三种方法的路径验证；
- 正负分支和解集检查；
- 表达式形式不同但数学等价的学生回答；
- 不等价回答和参考答案冲突；
- 模型结构化输出解析与修复；
- Reviewer 通过和要求重写两条路径；
- 主板书图层 push/pop 后状态一致；
- 互动提示和重试状态；
- API Key 不进入客户端和日志。

### 10.2 课堂体验样例

至少准备六道固定验收题：

- 两道一元一次方程；
- 一道因式分解法一元二次方程；
- 一道公式法一元二次方程；
- 两道配方法一元二次方程，其中一道包含分数或较难结构。

这些题用于回归测试，不作为现场生成的预写内容。

### 10.3 人工教研检查

对每道题检查：

- 能否指出整节课的一条主线；
- 学生是否知道为什么使用当前方法；
- 重点标记是否与讲解同步；
- 互动是否要求真实思考；
- 错误反馈是否促成再次尝试；
- 临时图层是否能顺利返回主线；
- 学生是否有机会独立完成近迁移题。

人工检查只能支持“讲解具备可演示质量”的结论，不能支持长期学习效果结论。

## 11. 首版验收条件

1. 用户可以输入一道人类未预置的一元一次或一元二次方程；
2. 系统通过配置的 OpenAI 兼容 API 现场生成；
3. 关键数学内容和最终答案通过独立校验；
4. 生成结果进入横屏 Pad 比例的全屏课堂；
5. 课堂包含渐进板书和至少两种重点表达方式；
6. 至少包含一个真正要求学生作答的互动；
7. 需要时能够进入临时讲解图层，并准确恢复主板书；
8. Reviewer 对整篇讲稿审核，而非按固定模板机械打勾；
9. 不合格结果被修订或明确拒绝；
10. 最终包含经过验证的近迁移题。

## 12. 后续升级边界

首版验证成功后，可以按实际问题逐步增加：

- 高质量 TTS 和数字人轨道；
- Tutor Agent 处理开放追问和动态教学路径；
- 独立的教学舞台设计 Agent；
- 学生长期状态和支架渐隐；
- 更多题型；
- 教研标注集和讲解质量基准。

这些能力不提前进入首版，以免掩盖“AI 是否能够为一道新题生成高质量讲解”这一核心问题。
