# 按课程 ID 持久化与恢复 Demo 设计

日期：2026-08-10
状态：已确认，待实施

## 目标

生成一节课后立即得到稳定的课程 ID，并把题目、完整课程结构和互动数据持久化。服务重启后，教师仍能输入该 ID 直接进入课程，不必再次调用模型或火山 TTS。

本版本只按课程 ID 查找课程。相同题目再次生成时创建新课程和新 ID，不做题干指纹命中或自动复用。

## 用户流程

### 首次生成

1. 教师输入题目、参考答案、可选参考解析、指定方法和讲解长度。
2. 系统完成教学设计、审稿、课堂编译与语音生成。
3. 系统先提交课程记录，再把生成任务标记为完成。
4. 生成页显示课程 ID，提供“复制课程 ID”和“进入课堂”。
5. 教师进入 `/lesson/{lesson_id}` 播放课程。

### 再次演示

1. 教师打开生成页，在“打开已有课程”区域输入课程 ID。
2. 页面先请求课程 API，确认课程存在且可读取。
3. 验证成功后进入 `/lesson/{lesson_id}`，不调用模型和 TTS。
4. ID 不存在、格式非法或记录损坏时，页面保留在生成页并显示明确提示。

### 服务重启

课程记录和音频保留在 `var/` 中。服务重启后，课程 API 按 ID 从 SQLite 加载并重新验证 `RuntimeLesson`，互动评估继续使用完整的服务端课程数据。

## 数据存储

使用 Python 标准库 `sqlite3`，数据库文件为：

```text
var/lessons.sqlite3
```

音频保持现有目录：

```text
var/audio/{lesson_id}/
```

数据库使用一张 `lessons` 表：

```sql
CREATE TABLE IF NOT EXISTS lessons (
  lesson_id TEXT PRIMARY KEY,
  problem_text TEXT NOT NULL,
  reference_answer TEXT NOT NULL,
  reference_solution_text TEXT,
  required_method TEXT,
  lesson_length TEXT NOT NULL,
  runtime_json TEXT NOT NULL,
  created_at TEXT NOT NULL
)
```

`runtime_json` 保存完整、未脱敏的 `RuntimeLesson`，包括互动正确答案、反馈和内部验证信息。对浏览器返回时仍通过现有 `public_lesson_payload` 移除这些私有字段。

课程 JSON 使用 Pydantic 的 JSON 序列化结果。读取时必须重新执行 `RuntimeLesson.model_validate_json`；不能解析或不能通过当前 schema 的记录按不可用处理，不把未经验证的数据送入课堂运行时。

`created_at` 使用 UTC ISO 8601 时间。SQLite 启用外键检查和合理的 busy timeout。每次保存单课使用事务与 `INSERT`，课程 ID 冲突时失败，不覆盖原课程。

## 存储边界

生成任务仍保存在进程内存中，因为任务只服务于当前生成过程；重启后无需恢复已经结束或中断的轮询任务。

课程存储抽象保留现有调用方式：

- `save_lesson(lesson)`：写入内存热缓存和 SQLite。
- `get_lesson(lesson_id)`：先查内存，未命中再查 SQLite、重新验证并放回内存。
- `get_interaction(lesson_id, interaction_id)`：通过 `get_lesson` 取得完整课程，因此重启后互动仍可用。

测试可以使用临时 SQLite 文件，避免触碰真实 `var/lessons.sqlite3`。生产 `create_app()` 默认传入项目级数据库路径；已有显式注入 store 的测试保持隔离。

## 生成一致性

课程只有在以下两步都成功后才标记生成完成：

1. TTS 已附加并写入音频文件。
2. 完整 `RuntimeLesson` 已成功提交到 SQLite。

数据库写入失败时，生成任务返回现有通用失败提示，不返回课程 ID。已经生成但未被课程记录引用的音频属于可清理的孤儿文件，本版本不增加后台清理任务。

SQLite 记录与音频目录不是一个跨文件系统事务。本 Demo 的可接受边界是“不会返回无法恢复的 ID”；后续若需要运营级清理，再增加孤儿音频扫描。

## API 行为

现有接口保持兼容：

- `POST /api/lessons/generate` 仍返回 `job_id`，每次调用都生成新课程。
- `GET /api/jobs/{job_id}` 在完成时返回持久化后的 `lesson_id`。
- `GET /api/lessons/{lesson_id}` 可以从 SQLite 恢复课程，并继续返回脱敏公开结构。
- `POST /api/interactions/evaluate` 可以对重启后恢复的课程进行判断。

不新增“按题干搜索”或“列出全部课程”的接口。课程 ID 是本版本唯一公开查找键。

## 页面设计

### 生成完成状态

现有生成进度区在任务完成后不再立即跳转，改为完成卡片：

- 标题：课程已保存
- 课程 ID：等宽、可选择文本
- 按钮：复制课程 ID
- 主按钮：进入课堂
- 次按钮：继续生成新课程

复制失败时保留可选择的 ID，并提示用户手动复制。

### 打开已有课程

生成页增加一个紧凑的“打开已有课程”区域：

- 单行课程 ID 输入框
- “打开课堂”按钮
- 提交前去除首尾空格
- 只允许安全 ID 字符与合理长度
- 先请求课程 API；404 显示“没有找到这个课程 ID”，其他连接错误显示“暂时无法读取课程”

学生课堂继续保持全屏横屏体验，不在板书区域、讲解字幕或互动卡片中显示课程 ID。课程 URL 自带 ID，可作为第二个复制入口。

## 安全与隐私

- SQLite 文件只保存在本机项目 `var/`，不通过静态目录暴露。
- API 继续隐藏参考答案、参考解析、互动正确答案和内部验证报告。
- ID 输入只用于构造经过 `encodeURIComponent` 的本机 API 与页面路径，不插入 HTML。
- 存储层拒绝路径式 ID、非法 schema 和重复 ID。
- 日志不输出模型或 TTS 密钥，也不输出完整参考解析。

## 测试标准

### 存储测试

- 保存课程后，新的 store 实例能从同一 SQLite 文件按 ID 读回完全等价的 `RuntimeLesson`。
- 重启模拟后，互动查找仍返回带正确答案的服务端互动。
- 不存在的 ID 返回 `None`。
- 损坏 JSON、schema 不兼容记录和重复 ID 安全失败，不能覆盖现有课。
- 数据库路径的父目录按需创建。

### API 测试

- 生成任务只在持久化成功后标记完成并返回 ID。
- 持久化失败时任务失败且不返回 ID。
- 新 app 实例可以读取此前保存的课程。
- 恢复课程的公开 API 仍然脱敏。
- 重启后互动评估仍正确。

### 页面测试

- 生成完成后显示课程 ID，而非立即跳转。
- 可以复制 ID、进入课堂或继续生成。
- 首页 ID 表单先验证课程，再导航。
- ID 不存在和网络失败有不同提示。
- 公式生成、课堂全屏布局和现有生成表单不回退。

### 现场验收

1. 生成参数根演示课，记录课程 ID。
2. 关闭并重新启动服务。
3. 在首页输入该 ID，直接进入课程。
4. 确认语音、KaTeX、同步高亮、板书、选择互动和反馈均可用。
5. 再次提交同一道题，确认创建不同 ID，而非自动复用。

## 非目标

- 按题干、答案或解析自动去重。
- 课程列表、搜索、删除、重命名、权限或账号体系。
- 多机共享数据库、对象存储和云端部署。
- 数据库 schema 迁移框架或历史课程自动升级。
- 孤儿音频的自动回收。
