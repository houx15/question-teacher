# 浅色课堂与语义重点标注设计

## 目标

本次修改解决两个直接影响 Demo 可信度的问题：

1. 全屏讲解页的深绿色背景过重，需要改为明亮、柔和、适合横屏 Pad 长时间观看的浅色课堂。
2. 当板书区只有一条公式时，整式圈注没有提供额外信息，反而显得 AI 在机械执行视觉动作。

生成页的输入流程、横屏全屏布局、语音、互动、临时图层和已有板书动作种类保持不变。

## 方案比较

### 方案 A：只替换颜色变量与 Prompt

优点是改动小。缺点是历史课件或模型偶发输出仍可能在单元素画面画出整圈，运行时无法兜底。

### 方案 B：浅色视觉系统 + 生成约束 + 运行时防线

这是本次采用的方案。视觉层统一改为“暖白数学纸”，生成规则要求重点必须指向局部语义对象；运行时在板书只有一个可见对象时忽略 `circle` 和 `box`，避免低价值整式包围。

### 方案 C：公式 AST 分词与局部几何标注

该方案能精确圈出系数、符号或项，但需要新的数学排版、目标定位和动作协议，超出本次视觉修正范围。后续若要追求可出版级公式动画，再单独设计。

## 视觉设计

课堂采用暖白、低饱和的纸张感：

- 页面背景为柔和米白，使用极轻的纸张纹理和暖色光晕，避免纯白刺眼；
- 课堂容器和板书面为浅灰白，通过细边框和内阴影建立层级；
- 正文与公式使用深墨蓝，次要信息使用灰蓝；
- 黄色用于当前重点，青绿色用于理由和正确反馈，珊瑚红只用于错误反馈；
- 顶栏、学习目标、字幕、互动卡和控制栏均使用浅色表面，不恢复左右分栏；
- 保留全屏 16:10 横屏 Pad 比例、现有字号层级和交互位置；
- 标注从“粉笔装饰”改为“纸上批注”：轻荧光笔、细下划线、清晰箭头和短标签。

## 重点标注规则

### 教学设计约束

- 重点动作必须回答“学生此刻应该看哪里，以及为什么”；
- 禁止为了制造动画而标注；
- 当画面只有一个公式或一个板书对象时，禁止对整个对象使用 `circle` 或 `box`；
- 需要强调单个公式内部的系数、符号、运算或条件时，Director 应先把该局部写成独立语义对象，再对局部使用 `focus`、`underline`、`arrow` 或短 `label`；
- `circle` 和 `box` 只用于多个对象中的区分、回指或比较；
- Review Agent 将无信息增益的整式圈注视为必须修正的问题。

### 运行时防线

板书状态机执行 `annotate` 时，统计当前可见的教学对象，忽略只有一个对象时针对它发出的 `circle` 或 `box`。该规则作用于新生成课件和已经保存的旧课件，不影响多对象比较中的有效圈注。

运行时不猜测公式内部的字符范围，也不把整式圈注自动替换为整式下划线，因为这种替换仍没有增加指向信息。

## 验证

- 静态测试检查课堂浅色主题变量、浅色浏览器主题色和语义标注 Prompt；
- Node 状态机测试证明单对象整圈被忽略、多对象圈注仍被保留；
- Python 全量测试验证生成、编译、API、TTS 和互动无回归；
- 在真实浏览器以横屏 Pad 尺寸检查开场、板书、互动、临时图层和返回主板；
- 视觉验证只能证明实现呈现符合本设计，不能替代真实学生对讲解重点的理解验证。
