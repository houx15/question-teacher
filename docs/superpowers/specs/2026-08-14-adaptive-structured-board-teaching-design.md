# AI 讲题 Demo：自适应教学推进与连续结构化板书设计

日期：2026-08-14
状态：已由用户审阅确认，可进入实施计划

## 1. 决策摘要

本设计解决两个已经在真实生成课程中暴露的核心问题：

1. 讲解虽然数学结论正确，但没有稳定地指出每一步为什么这样想、应该强调什么；
2. 板书虽然能够随语音出现，却更像内容卡片的堆叠，无法帮助学生形成连续、结构化的解题思维。

本版本在现有 Multi-Agent 备课流水线中新增一个可靠的私有中间成果
`TeachingProgression`，并将最终课堂生成调整为：

```text
题目、答案、参考解析
→ 还原数学解法与条件使用
→ 设计学生应经历的教学推进
→ Teaching Agent 改写成自然、顺畅的教师讲稿
→ 设计诊断互动与错因补讲
→ 编排连续板书、题干强调和自动滚动
→ 模拟学生并反复审核
→ 编译、火山 TTS、持久化、按课程 ID 重放
```

学生课堂继续保持全屏横屏 Pad 体验。板书采用单列连续布局，不再使用割裂的左右栏：

- 每一步由彩色圆角步骤标题建立结构；
- 标题下直接出现 16px 正文和 20–22px 关键公式；
- 当前步骤随思考过程展开；
- 已完成步骤保留标题与关键结论；
- 当前内容自动滚动到主要视区；
- 错误补讲在当前步骤内临时展开，结束后直接回到主线。

本设计是对
`2026-08-11-reasoning-trajectory-multi-agent-generation-design.md` 的增量细化，保留现有的
数学边界、审核收敛、私有记录、SQLite 课程 ID、火山 TTS 和失败原子性。

本设计明确替代旧规格中的两项课堂决定：

- 错误补讲后不要求学生在原题上再次作答，补讲结束直接恢复主线；
- 学生结构不再由独立左侧目录表达，改由单列板书中的彩色步骤标题和状态圆点共同表达。

若旧规格与本文在这两项上不一致，以本文为准。

## 2. 设计目标

### 2.1 教学目标

一节合格的讲解必须让学生在每个关键节点知道：

- 现在要解决什么问题；
- 为什么此刻想到这样做；
- 使用了题目中的哪个条件或已有结果；
- 具体数学操作是什么；
- 做完以后得到了什么；
- 下一步为什么由此产生。

数学讲解包含相互穿插的两类活动：

1. **构思**：观察条件和目标、形成想法、探索、比较与选择方法；
2. **执行**：代入、变形、计算、检查和表达。

课程不得把参考解析中的执行步骤直接改写成口播，也不得假设所有构思都在计算开始前一次完成。
执行过程中出现的新式子可以触发新的观察、提问和计划调整。

### 2.2 体验目标

- 学生听到的是自然的中文教师语言，而不是中间结构字段；
- 题干强调、板书和语音在同一个语义单元上同步；
- 板书建立逐步生长的解题结构，不提前剧透完整路径；
- 正确回答获得简洁确认，错误回答获得更深的针对性补讲；
- 错误补讲结束后直接继续主线，不强迫学生再次答对；
- 生成成功后以课程 ID 保存，演示时无需重新等待生成。

### 2.3 本版本不做

- 通用自动解题或正式批改；
- 学生自由输入公式作为主要互动方式；
- 根据长期学生画像实时重写整节课；
- 模型生成任意 HTML、CSS、坐标或自由动画；
- 模拟真实手写笔迹；
- 为每句话强行添加高亮、板书或互动；
- 向学生暴露备课 JSON、审核记录或 Agent 角色。

## 3. 样题产生的具体教学要求

样题：

> 若 $2n$（$n\ne0$）是关于 $x$ 的方程 $x^2-2mx+2n=0$ 的根，则 $m-n$ 的值为多少？

参考答案为 $\frac{1}{2}$。

本题的最低合格教学结构为：

### 第一步：理解方程的根

- 提问：“$2n$ 是这个方程的根，根代表什么？”
- 同步强调题干中的 `$2n$` 与“方程的根”；
- 知识锚点：“方程的根 → 代入方程后等式仍然成立”。

### 第二步：把 $x=2n$ 代入方程

- 提问：“方程里有 $m$、$n$、$x$，应该代入谁？”
- 强调“关于 $x$ 的方程”；
- 解释关于谁的方程，就把根代给谁，其余字母暂时看作数；
- 板书 `$x=2n$` 及代入式。

### 第三步：展开并化简

- 让学生选择正确的代入结果；
- 正确结果为 `$(2n)^2-2m\cdot2n+2n=0$`；
- 重点解释 `$(2n)^2=4n^2$`，诊断平方和乘法错误；
- 得到 `$4n^2-4mn+2n=0$`。

### 第四步：利用 $n\ne0$ 约去 $n$

- 引导学生观察每一项都有 $n$；
- 提问：“有公因式 $n$ 就一定可以约掉吗？”
- 此时才强调题干中的 `$n\ne0$`；
- 解释除以未知数前必须确认它不为零；
- 得到 `$4n-4m+2=0$`。

### 第五步：整理出 $m-n$

- 引导学生观察目标是 `$m-n$`，当前式子中出现 `$n-m$`；
- 解释二者互为相反数；
- 将式子整理为 `$-4(m-n)+2=0$`；
- 由学生完成最后结果，并用一句话总结符号易错点。

如果课程只计算出正确答案，却缺少“根的含义”“代入谁”“$n\ne0$ 的使用位置”或
“$n-m$ 与 $m-n$ 的关系”，审核必须判为不合格。

## 4. Multi-Agent 职责

### 4.1 Reference Material Analyst

负责：

- 识别题目条件、目标、数学步骤和最终结论；
- 标记每个条件的准确使用位置；
- 区分构思步骤和执行步骤；
- 补充参考解析省略的局部数学理由；
- 标记不明确或需要教学解释的跳步。

不负责课堂口语、互动表现和视觉布局。

### 4.2 Teaching Designer

负责把权威解法重构为学生应经历的 `TeachingProgression`：

- 每一步此刻面对的学生问题；
- 为什么现在处理它；
- 应观察的题干证据；
- 需要解释的知识和公式；
- 构思、探索、执行、检查之间的转换；
- 适合诊断互动的位置；
- 完成后留下的结构化结论；
- 下一步如何自然产生。

Teaching Designer 不写最终教师台词，也不决定像素布局。

### 4.3 Teaching Agent

负责把 `TeachingProgression` 改写成自然、连贯的教师讲稿：

- 用问题带学生观察和思考；
- 解释“为什么”，避免机械念步骤；
- 根据上下文组织自然过渡；
- 控制句长、停顿和信息密度；
- 同时提供学生看到的 `display_text` 与 TTS 使用的 `spoken_text`；
- 不改变已经冻结的数学依赖和教学重点。

Teaching Agent 可以优化语言顺序，但不能删除 `must_teach`，也不能把中间字段名称直接说给学生。

### 4.4 Interaction Designer

负责关键诊断互动：

- 说明为什么需要在这里暂停；
- 优先使用选择题，避免学生输入复杂公式；
- 为每个错误选项绑定具体错误类型；
- 指定错误后需要加深讲解的内容和深度；
- 指定临时补讲结束后的主线恢复位置。

错误回答是补充教学的证据，不是通关门槛。补讲结束后直接继续主线。

### 4.5 Classroom Director

负责把讲稿编排为可执行课堂：

- 题干圈注、高亮、遮罩和标记；
- 彩色步骤标题的揭示和状态变化；
- 关键文字与公式逐行写入；
- 当前重点的强调和讲后弱化；
- 单列板书自动滚动；
- 错误补讲区的打开、更新、关闭和主线恢复；
- 语音单元与视觉动作的顺序绑定。

Classroom Director 只能选择受控动作，不能生成任意页面代码。

### 4.6 Student Simulator 与 Lesson Reviewer

Student Simulator 至少模拟：

- 跟上主线并回答正确的学生；
- 不理解概念含义的学生；
- 代入对象错误的学生；
- 平方、乘法或符号计算错误的学生；
- 忽略非零、定义域等条件的学生；
- 得到中间式后不知道如何连接目标的学生。

Lesson Reviewer 检查数学正确性、思维推进、教学重点、语言自然度、互动诊断力、板书可读性和
语音同步，并把问题路由给最早应负责修改的 Agent。

## 5. 私有中间成果：TeachingProgression

`TeachingProgression` 是可靠性优先的结构化教学蓝图，只在服务端保存。

每个 `TeachingStep` 至少包含：

| 字段 | 含义 |
| --- | --- |
| `step_id` | 稳定步骤 ID |
| `phase` | `construct`、`explore`、`execute` 或 `check` |
| `student_problem` | 学生此刻真正要解决的问题 |
| `why_now` | 为什么现在处理这个问题 |
| `evidence_targets` | 此刻应该观察或强调的题目证据 |
| `guiding_questions` | 引导学生形成想法的问题 |
| `knowledge_anchor` | 需要沉淀的概念、条件或公式 |
| `checkpoint` | 是否需要诊断互动及诊断目标 |
| `reveal` | 学生思考后才揭示的结论 |
| `math_action` | 权威数学动作及前后状态 |
| `directory_question` | 步骤形成前的思考问题 |
| `directory_label` | 步骤形成后的学生可见标题 |
| `board_summary` | 完成后保留的关键板书 |
| `error_tip` | 易错点及其数学来源 |
| `transition_question` | 引出下一步的自然问题 |

约束：

- 每个数学动作必须关联一个教学目的；
- 每个题目条件必须记录准确使用步骤；
- 每个 `must_teach` 必须被讲稿和板书共同承接；
- 步骤标题在学生形成思路后才出现，不提前显示完整答案路径；
- 中间成果允许结构化、偏工程化，最终 Teaching Agent 负责消除人机感。

## 6. 最终讲解与同步单元

Teaching Agent 将每个步骤写成若干个短讲解单元。每个单元包含：

```text
lesson_step_id
display_text
spoken_text
actions_before
actions_after
interaction_boundary
```

示例：

```text
display_text:
  我们要求的是 m-n，而式子中出现的是 n-m。

spoken_text:
  我们要求的是 m 减 n，而式子中出现的是 n 减 m。

actions_before:
  - emphasize_problem_target(m-n)

actions_after:
  - append_board(n-m=-(m-n))
```

短讲解单元是语音与画面同步的最小单位。动作在单元开始或结束处确定性触发，不要求模型生成
毫秒级时间戳，也不允许一整段音频只绑定一个模糊的板书 Beat。

### 6.1 公式朗读

`display_text` 保持标准数学显示，`spoken_text` 使用中文课堂读法：

- `m-n` → “m 减 n”；
- `n\ne0` → “n 不等于零”；
- `(2n)^2` → “二 n 整体的平方”；
- `\frac{1}{2}` → “二分之一”。

Teaching Agent 提供首选读法，服务端数学朗读规范化器负责确定性兜底。审核必须检查显示公式中的
运算符没有在语音中漏读。无法安全朗读的表达式应阻止生成，而不是静默删除符号。

## 7. 互动与自适应讲解深度

每个 `InteractionCheckpoint` 包含：

- `diagnostic_goal`：要判断学生是否理解什么；
- `options`：学生可见选择；
- `error_code`：每个错误选项对应的具体错因；
- `correct_response`：正确后的简洁确认；
- `remediation`：错误后的补讲内容；
- `resume_at`：补讲结束后的主线位置。

讲解深度规则：

- **正确**：确认关键理由，避免重复完整计算；
- **概念错误**：回到概念或条件含义，增加例子或反例；
- **计算错误**：拆解具体计算步骤，逐项显示中间过程；
- **目标连接错误**：重新比较当前式子与题目所求；
- **补讲结束**：记录学生证据，关闭临时区并直接继续主线。

第一版不要求错误后再次作答。后续如果要评估掌握程度，可在独立的迁移题中验证，而不是让当前讲解循环卡住。

## 8. 连续结构化板书

### 8.1 布局

课堂采用单列连续板书：

```text
题目区域

● 第一步：理解方程的根     ← 彩色圆角步骤标题
  方程的根 → 代入后等式成立
  x = 2n

● 第二步：代入方程
  (2n)² - 2m·2n + 2n = 0
  ...
```

不再使用独立左侧目录和右侧内容区。步骤标题本身同时承担目录、进度和当前状态表达。

### 8.2 字号与密度

- 正文：16px；
- 关键公式：20–22px；
- 步骤标题：14–15px；
- 题干：15–16px；
- 辅助提示：13–14px。

这些尺寸以横屏 Pad 为主，不按远距离教室大屏设计。

### 8.3 步骤状态

每个步骤在运行时经历：

```text
unseen → questioning → active → completed
                         ↓  ↑
                      supporting
```

- `unseen`：不提前显示；
- `questioning`：只显示问题和正在观察的题目证据；
- `active`：揭示彩色标题，正文和公式逐行出现；
- `supporting`：在当前步骤内展开错误补讲；
- `completed`：保留标题和关键结论，弱化历史重点，可由学生回看。

### 8.4 受控板书动作

第一版动作集合：

- `reveal_step_header`；
- `append_board_line`；
- `emphasize_problem_target`；
- `emphasize_board_target`；
- `soften_emphasis`；
- `complete_step`；
- `scroll_to_step`；
- `open_supporting_explanation`；
- `close_supporting_explanation`。

约束：

- 单独存在的唯一元素不得做无意义圈注；
- 高亮只强调当前语义证据，不要求每个讲解单元都有高亮；
- 已讲过的重点可以弱化，但不能全部变成相同完成颜色；
- 新内容出现时，播放器保证当前步骤始终处于主要视区；
- 模型提供语义目标 ID，程序负责布局、换行、字号、颜色和滚动。

## 9. 课堂运行状态

运行时由确定性播放器维护：

- 当前步骤；
- 当前讲解单元；
- 当前题干与板书强调；
- 已完成步骤及其摘要；
- 是否等待互动；
- 是否处于错误补讲；
- 补讲结束后的恢复位置；
- 音频播放、暂停和恢复状态。

暂停时所有待触发动作一并暂停；恢复时从剩余时间继续；取消后不得触发旧动作。互动出现时主线音频和
动作冻结，回答处理完成后从确定的 `resume_at` 恢复。

## 10. 教学质量审核

审核不采用可互相抵消的总分。以下均为硬性条件。

### 10.1 解题结构

- 每个关键数学步骤均被覆盖；
- 每一步说明问题、理由、证据、动作、结果和下一步；
- 题目条件在真正使用时被明确指出；
- 计算正确但缺少构思理由仍判为不合格。

### 10.2 教学重点

- 每个 `must_teach` 同时出现在讲稿与板书；
- 重点与对应题干证据建立引用；
- 方法总结和易错点来自本题真实推理，不是通用口号。

### 10.3 学生可理解性

- 学生能够知道为什么这样想，而不仅是下一步做什么；
- 互动错误选项绑定真实错因；
- 错误补讲比正确确认更深入，并且只补当前缺口；
- 互动前不泄露答案。

### 10.4 语言与语音

- 最终台词为自然简体中文；
- 不朗读内部结构标签；
- 公式显示与朗读语义一致；
- 减号、分数线、幂、括号和不等号等关键运算不得漏读。

### 10.5 板书演出

- 步骤标题随思路形成出现；
- 板书保留知识锚点和关键推导，不抄写整段口播；
- 题干与板书强调在对应讲解单元触发；
- 当前步骤自动滚动可见；
- 临时补讲不破坏主线内容和恢复位置；
- 16px 正文在横屏 Pad 上可读且信息密度合理。

### 10.6 收敛

审核不限于两轮：

1. 模拟不同学生完成整课；
2. Reviewer 给出带证据的问题；
3. Orchestrator 找到最早责任 Agent；
4. 只重建该成果和受影响的下游成果；
5. 重新模拟和审核；
6. 全部硬性条件通过后才允许编译和 TTS。

保留有限安全轮次和无进展检测。达到安全上限仍未通过时，课程生成明确失败，不降低标准保存半成品。

## 11. 生成、持久化与兼容性

- 公开学生课堂继续使用稳定的 `RuntimeLesson`；
- `TeachingProgression`、审核发现、错误分支和完整讲稿属于私有生成记录；
- 受控新动作由编译器映射为播放器可执行事件；
- 旧课程 ID 保持可读取，使用旧版板书表现；
- 新生成课程标记私有生成版本，以便诊断和 Golden Set 对比；
- 只有教学审核、编译和 TTS 全部成功后，才原子保存课程、私有记录和音频；
- 任一阶段失败均不得留下可打开的半成品课程或覆盖旧课程音频。

## 12. 验收测试

### 12.1 结构与验证测试

- `TeachingProgression` 字段、ID、引用和顺序完整；
- 每个条件、数学步骤、`must_teach`、互动和板书动作可追踪；
- 非判别性强调、无关高亮、答案泄漏和无效恢复位置被拒绝；
- 错误分支不得改变权威数学主线。

### 12.2 语音测试

- `m-n` 必须朗读“m 减 n”；
- 覆盖分数、幂、不等式、括号、正负号和常见函数；
- 显示公式与朗读语义不一致时阻止生成；
- 火山 TTS 返回的音频与讲解单元一一对应。

### 12.3 播放器测试

- 横屏 Pad 典型尺寸至少覆盖 1280×800 和 1024×768；
- 正文计算样式为 16px，关键公式层级正确；
- 题干强调、板书追加和语音单元同步；
- 步骤增长、完成弱化和自动滚动正确；
- 暂停、恢复、取消和互动不会触发过期动作；
- 错误补讲打开、关闭并从准确位置继续。

### 12.4 学生分支测试

样题至少模拟：

- 正确选择代入式；
- 把平方算错；
- 代入错误变量；
- 忽略 `$n\ne0$`；
- 混淆 `$n-m$` 与 `$m-n$`。

每个错误必须触发不同的补讲，补讲结束后主线继续且不重复已正确理解的部分。

### 12.5 教学 Golden Set

使用现有多题型 Golden Set 比较版本，覆盖方程、不等式、分式、函数、无图几何、统计概率和应用题。
当前参数根样题作为重点人工审阅案例，但不能成为唯一通过样题。

## 13. 完成标准

本版本只有在以下条件同时满足时完成：

1. 新课程通过 `TeachingProgression` 生成；
2. Teaching Agent 输出自然讲稿和独立语音文本；
3. 诊断互动能够按错因改变补讲深度；
4. 学生课堂采用单列连续结构化板书；
5. 16px 正文、公式层级和自动滚动通过真实横屏 Pad 浏览器验收；
6. 样题完整呈现五步教学逻辑及相应题干强调；
7. `m-n` 等公式读音经真实火山 TTS 验收；
8. 多题型 Golden Set 和全量自动化测试通过；
9. 审核失败、编译失败、TTS 失败和持久化失败均不产生半成品课程；
10. 已生成课程可以凭课程 ID 立即重放。
